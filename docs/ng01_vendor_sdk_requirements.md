# NG01 遥操需要厂家确认的 SDK 能力

当前工程使用华成具身 HCXSDK V2.3.9（`xoip`）。安全首版通过保护模式下的
`moveJoints2` / `moveJointsMulti2` 下发 IK 关节目标，不使用解除保护后的
`PluseToServo`。

在把系统从低速联调升级为正式实时遥操前，请厂家提供或书面确认：

1. `moveJointsMulti2` 连续调用时是覆盖旧目标还是排队，以及支持的最高频率。
2. `MultiRobotActionParam` 是否支持 `interpolation_en`，确保双臂可原子打断旧轨迹。
3. `PluseToServo` 的推荐周期、最大周期抖动、单周期关节增量和返回错误定义。
4. 双臂批量关节透传接口；当前 V2.3.9 只暴露逐臂 `PluseToServo`。
5. 通信丢失 watchdog：超时阈值、停车方式，以及断开客户端后的控制器行为。
6. 无需关闭控制器保护的实时位置流接口，或由控制器执行的速度/加速度/限位保护。
7. 高频状态反馈接口及时间戳，目标至少 100 Hz；当前轮询反馈周期默认 40 ms。
8. Linux x86_64 的 CPython 3.11/3.12 wheel，避免 Python 3.10 broker RPC 引入抖动。
9. 与 SDK V2.3.9 匹配的控制器固件版本、升级包、变更记录和官方遥操示例。
10. 急停、清轨迹、下使能在规划流和透传流中的确定性时序说明。

拿到第 1、2 项即可判断现有保护模式能否稳定做到 20-30 Hz；拿到第 3-8 项后，
才能安全评估是否切换到类似法奥 `ServoJ` 的实时透传模式。
